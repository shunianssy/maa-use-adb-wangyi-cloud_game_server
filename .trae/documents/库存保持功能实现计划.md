# 库存保持（仓库维持）功能实现计划

## Context（背景）

用户希望在一键长草中新增「库存保持」功能，对应 MAA 官方 GUI 的「仓库维持」能力：

1. 新增任务开关「库存保持」，开启后可勾选 4 组保持项：低级芯片（全职业，目标 20）、高级芯片组（全职业，目标 20）、采购凭证/红票（目标 20）、技巧概要·卷3（目标 200），目标数量可编辑；
2. 勾选后：完成「领取奖励」后扫描仓库 → 计算缺口 → 规划下一次理智作战（次数 auto，界面显示"打什么、哪一关"）；
3. 优先级：**每周剿灭 > 库存保持 > 理智作战配置**（库存保持先按规划刷缺口，理智作战随后按原配置执行，消耗剩余理智）。

### 已完成的技术验证（关键结论）

| 结论 | 说明 |
| --- | --- |
| `Depot` 任务类型可用 | MaaCore v6.17.5 已实测接受 `AsstAppendTask("Depot", "{}")`（返回合法 task_id） |
| 仓库数据经回调返回 | `SubTaskExtraInfo`(msg=20003) → `what="DepotInfo"`、`details.done`(bool)、`details.data`(JSON 字符串 `{"物品ID":数量}`)；识别中 done=false 渐进上报，done=true 为最终结果 |
| `Fight.drops` 停止条件可用 | 已实测接受；语义为「本次任务累计掉落数达到即停」（Core 仅支持 Farm 模式，Target Inventory 需 UI 层换算为"缺口数量"） |
| 物品/关卡映射 | 使用官方资源 `item_index.json`、`stages.json` 核对（见下表） |

### 预设映射（已核对官方资源）

### 行为设计决策

1. **执行时机**：本次运行立即执行（扫描 → 规划 → 刷关一步完成，不跨运行保存规划）；
2. **规划范围**：只刷「第一个有缺口的关卡」（按：低级芯片 → 高级芯片组 → 采购凭证 → 技巧概要 的顺序；同一关卡取缺口最大的目标物品），界面显示该计划；下次运行重新扫描仓库再规划；
3. **理智药**：沿用「作战设置」中的理智药配置（关闭 / AUTO / 指定数量）；
4. **执行顺序**：`awaken → reward → recruit → infrast → annihilation → inventory → combat → credit`；
5. **失败不阻断**：仓库识别失败/超时（上限 6 分钟）、无缺口、未勾选任何保持项时，记录日志并跳过库存保持，继续后续任务。

### 2. [maa_coordinator.py](file:///s:/netease_cloud_game_server/maa_coordinator.py)（核心）
- 新增常量 `INVENTORY_PRESETS`（保持项 key → 中文名 + 关卡列表 + 每关目标物品 id/名，按上表硬编码）；
- 新增 `INVENTORY_ITEM_ORDER`（勾选顺序：chip_low → chip_high → certificate → skill_summary）；
- 新增纯函数（便于测试）：
  - `inventory_gaps(depot, inventory_opt) -> List[Dict]`：逐关卡计算缺口，每关取缺口最大的目标物品，返回全部缺口计划（`{key, stage, item_id, item_name, have, target, gap}`）；
  - `plan_inventory(depot, inventory_opt) -> Optional[Dict]`：返回第一个缺口计划（无缺口返回 None）；
  - `build_inventory_fight_params(plan, fight_opt) -> str`：构造 Fight 参数 `{stage, medicine(沿用作战设置), stone:0, times:FIGHT_TIMES_AUTO, series:0, drops:{item_id: gap}, client_type:"Official"}`；
- `TASK_EXEC_ORDER` 调整为 `["awaken", "reward", "recruit", "infrast", "annihilation", "inventory", "combat", "credit"]`，并更新注释说明优先级；`DEFAULT_TASK_MAP["inventory"]` 保留 `"Depot"` 仅作展示；
- `TaskStatus` 新增 `_inventory_plan` 字段 + `set_inventory_plan()`，`start_run` 复位，`snapshot()` 输出 `inventory_plan`（深拷贝）；
- `MaaCoordinator` 新增：
  - `_run_inventory(assist) -> _TaskOutcome`：① append+start `Depot` 任务并等待（轮询 `_depot_done` 事件/任务结束，响应 `_stop_flag`，6 分钟超时保护）→ ② `plan_inventory` 计算规划并写入状态 → ③ 有缺口时追加库存保持版 Fight（`build_inventory_fight_params`）复用 `_wait_task` 等待；
  - `_on_depot_info(details)`：解析 DepotInfo 回调（兼容 msg 20003/10003，`done` 置事件、`data` JSON 字符串解析过滤为 `{str: int}`），线程安全（锁保护）；
  - `_on_maa_msg` 新增 `20003/10003 + what=="DepotInfo"` 分支；
  - `_run` 主循环对 `inventory` 特判（不经过 `build_task_params` 常规路径），执行前把 `_current_key/_current_type` 设为 `("inventory", "Fight")` 保证回调日志可读。
